从实验台到展台——双臂机器人参展前的最后一次系统联调

发表于2026-08-21本文字数3.4k字阅读时长3 分钟
  • RoastDuck
首页项目

一句话总结： 一台机器人能够在实验室里动起来，只代表开发走完了前半程；当它需要被搬到展台、连续运行并让陌生观众看懂时，稳定性、装配、恢复能力和现场协作才真正成为主角。

# 双臂机器人终于要离开实验台了

这一阶段的重点仍然是七自由度双臂机器人，但目标已经发生了变化。

前面做模型适配、VR 遥操作和第二台样机装配时，我更关心的是功能能不能实现：关节是否能通信、机械臂能不能按照指令运动、仿真中的控制链路能否迁移到实机。临近世界机器人大会，问题变成了另一种形式：这套系统能不能以一个完整、稳定、可展示的状态出现在现场。

因为要参加展出，前两天基本都在继续组装和调试双臂机器人。到了这个阶段，没有继续增加复杂功能，而是把已有部分调好、装好，尽量减少演示现场的不确定性。

这让我第一次明显感受到，实验样机和展台样机虽然是同一台机器，对工程状态的要求却并不一样。

# 能运行和能展示，中间还差什么？

在实验室里调试时，偶尔重启一次程序、重新连接一次通信，或者临时调整一根线都很正常。开发人员知道每个模块在哪里，也知道出现问题后应该从哪一层开始排查。

但展台上的机器人不能依赖这些隐含知识。它需要在有限时间内完成上电、连接和演示；出现异常后，也要尽可能快速地恢复，而不是现场重新分析整套系统。

对于这套双臂平台，参展前真正重要的工作主要集中在几个方面：

  • 两条机械臂及外壳是否完成可靠装配；
  • 关节模组的 CAN 通信和 ID 对应关系是否正确；
  • 关节零点、方向和活动范围是否符合控制程序预期；
  • 控制板、通信板和线束是否连接牢靠；
  • 整套系统能否在重新上电后恢复到可运行状态。

这些检查没有新增一个“看得见的新功能”，却决定了机器人在现场是一个可以重复演示的系统，还是只能在特定环境下偶尔跑通的原型。

# 最后阶段不再追求功能数量

项目开发时，人很容易不断往系统里加东西：新的动作、更复杂的控制逻辑、更漂亮的交互界面。但临近展示，继续增加功能往往意味着引入新的变量。

这一阶段更合理的做法，是先冻结演示范围，把注意力放到一条最稳定的链路上：

完成机械装配
      ↓
确认关节通信与零点
      ↓
验证基础动作
      ↓
重复执行演示流程
      ↓
记录异常后的恢复方法

对展台演示来说，一套简单但能够重复运行的动作，通常比一套复杂却容易中断的功能更有价值。

# PCB Layout：另一条没有停下来的硬件线

在双臂机器人进入最后装配的同时，我也继续尝试推进陪伴机器人低成本版本的 PCB Layout。

上一阶段已经基本完成原理图，也验证了麦克风接入和语音输入链路。现在需要把这些在逻辑上已经连接好的器件，真正放进一块尺寸有限的板子里。

做到 Layout 后，我越来越能理解为什么原理图完成并不意味着 PCB 已经完成了一半。原理图关心的是网络关系，而 Layout 还要同时面对：

  • 器件应该如何分区；
  • 电源和地应该怎样组织；
  • 音频信号如何避开高噪声区域；
  • 接口朝向能否适应实际装配；
  • 走线能否在有限层数和面积内完成。

这些问题没有唯一答案，而且会互相影响。为了缩短某条走线而移动一个器件，可能会让接口位置变差；为了把板子做小，又可能压缩电源和敏感信号之间的距离。

目前这部分还在继续摸索。相比直接用开发板搭原型，PCB Layout 更像是在做一组连续的取舍：尺寸、成本、布线难度和可维护性之间，很难同时取到最优。

# 到大会现场：演示也是系统的一部分

完成主要装配后，我们提前到大会现场进行了彩排和场地准备。除了机器人本身，还需要确认展台位置、设备摆放、人员引导和现场流程。

以前做项目时，我通常把系统边界画在机器人周围：传感器、控制器、执行机构和软件组成了完整系统。真正进入展会后才发现，演示流程其实也是系统的一部分。

观众不会先阅读项目文档，也不会等待开发人员慢慢进入调试环境。他们往往只通过很短的一段动作来理解这台机器人在做什么。因此，现场展示不仅要求设备能运行，还要求演示目标足够明确、启动步骤足够短、异常恢复足够直接。

在大会交流中，一场题为“机器人关节模组量产突破与未来趋势”的高峰对话给我留下了较深印象。北京航空航天大学蔡茂林教授与多家关节模组、机器人企业代表围绕核心部件的量产与产业化展开讨论。相比单独看产品参数，这类交流更能让人看到机器人从样机走向产品时真正需要解决的问题：性能只是起点，一致性、可靠性、成本控制和批量交付能力同样关键。

另一场技术分享来自中国信息通信研究院人工智能研究所具身智能与机器人部副主任、高级工程师张蔚敏，内容涉及具身智能领域的行业标准 YD/T 6770-2026《人工智能 关键基础技术 具身智能基准测试方法》。从现场展示的内容来看，该标准面向仿真与真实环境下的具身智能系统，覆盖模型及部署后的完整系统，并对“感知—决策—执行”全流程能力进行测试。这让我意识到，机器人能力不仅要被实现，还需要通过统一、可复现的方法进行评价，才能让不同技术路线具备可比较的工程尺度。

综合现场的产品展示与技术讨论，可以更清楚地看到行业关注点已经不只停留在运动效果，还延伸到了稳定性、部署成本、场景适配、测试标准和长期维护。

这也是为什么“演示成功”不能只理解为机器人完成了一次动作。真正有价值的演示，应该让人看到技术能力，同时也能看出它与实际场景之间的联系。

# 项目交接：技术工作不只存在于代码里

活动结束后，我还完成了一部分工作交接，接手了物料出入记录和其他项目资料。

这件事看起来与机器人开发关系不大，但从工程角度看，物料和资料其实决定了项目是否可追溯。一个模块为什么选这个型号、某块板子现在处于什么状态、设备借给了谁、哪份代码对应哪台样机，如果这些信息只存在于某个人的记忆里，人员变化后就很容易断层。

尤其是硬件项目，代码仓库只能保存软件，无法自动记录手里那块控制板是否损坏、某个关节模组是否返修、线束是否已经改版。要让项目能够继续推进，还需要把实物状态和文档对应起来。

我更希望后续资料至少能够回答三个问题：

  1. 现在有什么：硬件、配件、代码和文档是否齐全；
  2. 目前是什么状态：可用、待测、损坏还是正在维修；
  3. 下一步怎么继续：环境如何启动、设备如何连接、问题排查到哪里。

这类记录平时不显眼，但在项目交接和故障排查时，往往比一份只写结果的总结更有用。

# 从开发完成到工程完成

这一阶段让我重新理解了“完成”这个词。

程序写完，不代表机器人已经完成；机械臂装起来，也不代表系统已经完成；甚至现场成功演示一次，也不能证明它已经具备长期运行能力。

真正的工程完成，还包括稳定启动、重复运行、异常恢复、资料留存和后续维护。很多时候，最后这段工作没有新的算法，也没有明显的性能提升，却决定了前面的开发成果能不能被真正使用。

这次最大的体会： 从实验台走向展台，并不是给机器人换一个摆放位置，而是把只对开发者友好的原型，整理成一套别人也能理解、运行和接手的系统。

# 写在最后

双臂机器人完成装配并进入大会现场，意味着前一阶段的软件和硬件工作终于在真实设备上汇合。与此同时，陪伴机器人的 PCB 仍在 Layout 阶段继续推进，另一条硬件产品化路线才刚刚开始。

一边是已经走到展示环节的整机，另一边是刚从原理图走向电路板的硬件。它们所处阶段不同，但考验的是同一种能力：不只让技术成立，还要让它成为一个可以稳定存在、持续迭代的工程系统。
