两块屏幕拼出一张脸——低成本陪伴机器人硬件联调

发表于2026-08-02本文字数2.5k字阅读时长2 分钟

一句话总结： 本周完成了低成本陪伴机器人样机的基础组装，在 ESP32-S3 上跑通“小智”并实现左右眼双屏同步显示，同时通过测量 DOUT 信号定位了一块数字麦克风的硬件故障。

# 这周的目标：先让样机有一张“脸”

本周的主要工作，是组装低成本陪伴机器人样机，并把基础程序部署到 ESP32-S3 上进行第一轮联调。

软件部分沿用“小智”作为语音交互框架，面部则采用两块独立显示屏：左屏显示左眼，右屏显示右眼。这个结构很适合机器人头部造型，但也意味着原本为单屏设计的表情系统不能直接照搬。

这一阶段我没有急着同时联调整套机器人，而是把目标拆成四条最基础的链路：

模块 首轮验证目标
ESP32-S3 稳定启动并运行“小智”基础程序
双显示屏 两块屏幕能够被独立驱动
表情系统 左右眼资源正确拆分并同步切换
数字麦克风 能够持续输出有效音频数据

模块拆开验证，可以避免显示、音频和程序同时出问题时互相干扰，也更容易判断故障究竟属于软件还是硬件。

# 双屏表情：难点不在素材，而在渲染结构

表情资源使用了乐鑫提供的现成方案。真正需要修改的不是眼睛长什么样，而是它原本默认只有一块画布，左右眼会一起绘制在同一块屏幕上。

当前样机使用两块物理独立的屏幕，每块屏幕只负责一只眼睛。因此，显示逻辑需要从“一张画布画完整张脸”改成“两张画布协同更新”：

完整表情状态
      ↓
拆分左右眼绘制区域
      ↓
左眼画布 → 左侧显示屏
右眼画布 → 右侧显示屏
      ↓
同一时刻提交刷新

我对显示逻辑做了几项调整：

  • 左侧屏幕只输出左眼区域；
  • 右侧屏幕只输出右眼区域；
  • 两块屏幕分别维护自己的显示内容；
  • 表情切换由同一个状态驱动；
  • 更新时尽量保持同步，避免左右眼短暂错位。

最后一条尤其重要。双屏并不只是“能各自亮起来”就算完成，如果两边刷新时序差异过大，机器人会在表情切换时出现一只眼睛先动、另一只后动的割裂感。

# 两块屏幕同时接入后的异常

调试初期，两块屏幕同时连接 ESP32-S3 后出现了显示异常。单独测试时能工作的模块，组合到一起却不稳定，这是硬件联调中很典型的情况。

我重新检查了屏幕供电、通信线和引脚连接，并调整接线。双屏随后恢复正常，左右眼分屏和多种表情切换也顺利跑通。

最终效果达到了预期：两只眼睛可以分别显示在两块屏幕上，并在切换表情时保持一致。相比单屏方案，双屏增加了接线、片选和刷新同步的复杂度，但它给机器人头部结构留下了更自由的设计空间，也让面部表现更接近真正的两只眼睛。

调试心得： 单模块通过不代表组合后一定正常。每增加一个外设，都要重新检查供电、总线资源、引脚冲突和刷新时序。

# 麦克风没有数据：先测关键引脚

显示部分跑通后，我继续测试语音输入链路，但程序始终收不到有效的麦克风数据。

一开始，排查方向主要是供电、接线和引脚定义。数字麦克风不像模拟麦克风那样直接输出连续电压，而是依赖时钟和数字数据线与主控通信。软件侧收不到数据时，原因可能是引脚配置错误、时钟没有输出、数据线连接异常，也可能是模块本身已经损坏。

使用万用表测量后，我发现麦克风模块的 DOUT 引脚电平表现异常。重新检查供电和信号线后，现象依旧存在，因此基本排除了简单的接线问题，初步判断为模块硬件故障。

由于这块麦克风已经无法继续承担验证任务，我重新申请购买了新的模块。新模块到货后会按下面的顺序测试：

  1. 确认供电电压和地线正常；
  2. 检查时钟与数据引脚连接；
  3. 验证 ESP32-S3 能否持续读取原始音频数据；
  4. 最后再接入“小智”的语音识别链路。

这次问题提醒我，调试数字音频时不能只盯着程序日志。硬件模块损坏时，软件有时不会给出清晰报错，只会一直等不到有效数据。直接测量关键引脚，往往能更快缩小范围。

# 顺带完成一次工业视觉可行性验证

除陪伴机器人外，本周还做了一次工业视觉缺陷检测的初步测试。我使用现有检测程序验证了多组样本，观察软件能否识别目标缺陷，并判断当前方案是否值得继续推进。

常规样本已经可以完成基本检测，说明现有方案具备可行性。对于表面纹理复杂、缺陷边界不明显的样本，识别仍会受到干扰，后续需要加入更多真实样本，再决定是调整规则、优化成像条件，还是继续修改检测策略。

这一阶段的目标只是确认方向，而不是给出最终指标。先回答“方案能不能继续做”，再投入更多时间追求稳定性和精度，能避免在不合适的路线中过早消耗资源。

# 本周完成情况

这一周完成了以下节点：

  • 组装低成本陪伴机器人样机的基础硬件；
  • 在 ESP32-S3 上部署并启动“小智”基础程序；
  • 完成两块显示屏的独立连接与显示测试；
  • 将完整表情拆分为左右眼两路画面；
  • 实现双屏表情的同步切换；
  • 定位数字麦克风 DOUT 引脚异常；
  • 重新申请麦克风模块；
  • 完成工业视觉缺陷检测的初步可行性测试。

# 下一步计划

接下来的优先级很明确：

  1. 新麦克风到货后，先完成原始音频数据验证；
  2. 把麦克风接回“小智”，打通语音输入链路；
  3. 优化双屏刷新时序和表情切换细节；
  4. 整理线束与安装结构，减少临时接线带来的不稳定；
  5. 在基础硬件稳定后，再推进外壳和整体交互效果；
  6. 为工业视觉测试补充复杂纹理和弱缺陷样本。

# 写在最后

这周最有成就感的瞬间，是两块屏幕终于同步显示出一双完整的眼睛。它看起来只是一个表情效果，背后却涉及画布拆分、双屏驱动、接线检查和刷新同步。

麦克风故障则是另一类提醒：遇到“程序收不到数据”时，不能默认问题一定在代码里。硬件、供电和信号本身同样需要被逐层验证。

做样机的过程，就是把每一个“应该可以”变成测量过、观察过、能够重复出现的“确实可以”。
