这篇文章用于集中记录工作中经常使用的 CAN 调试命令和标准操作流程。内容按功能分节整理，后续遇到新的命令、参数或故障时，可直接在对应章节中补充。

# 使用说明

  • 本文默认使用 CAN 接口 can1，实际环境不同时需替换。
  • 写入模组参数前，先确认 CAN ID、波特率和目标 ID，避免操作错误设备。
  • 参数写入应依次完成“查询、修改、复查、保存、再次确认”，避免修改未持久化。
  • 示例中的 601 和 602 分别表示 CAN ID 0x601 和 0x602。
  • 修改本文后，同步更新 front matter 中的 updated 时间和文末维护记录。

# SocketCAN 接口与日志查看

# 实时查看 CAN 日志

使用 candump 实时查看 can1 接口上的 CAN 帧：

candump -e -x can1

# 处理 read: Network is down

执行 candump 时如果出现以下错误：

read: Network is down

这通常不是 Ubuntu 的普通网络断开，而是 SocketCAN 的 can1 接口处于 DOWN 状态。设备重启后，如果接口没有自动拉起，也会出现这一问题。

# 1. 查看接口状态

ip -details -statistics link show can1

# 2. 重新初始化接口

下面以 1 Mbit/s 波特率为例：

sudo ip link set can1 down
sudo ip link set can1 type can bitrate 1000000
sudo ip link set can1 up

# 3. 再次确认接口状态

ip -details -statistics link show can1

正常情况下，应能看到类似状态：

can1: <NOARP,UP,LOWER_UP>
state UP
can state ERROR-ACTIVE
bitrate 1000000

确认接口恢复后，再重新查看 CAN 日志：

candump -e -x can1

如果接口仍无法进入 UP 或 ERROR-ACTIVE 状态，应继续检查 CAN 设备驱动、终端电阻、线束连接、收发器供电及总线波特率是否一致。

# 修改 Motorevo 关节模组 ID（泉智博）

# 参数与计算规则

参数 含义
OLD_ID 当前 Motor ID
NEW_ID 目标 Motor ID
OLD_CAN_ID 0x600 + OLD_ID
NEW_CAN_ID 0x600 + NEW_ID
Motor ID Index 0x24
Read 0x04
Write 0x15
NEW_ID_INT32_LE 将新的 Motor ID 转换为 32 位小端整数

例如，将 Motor ID 从 1 修改为 2 时：

项目 值
OLD_ID 1
NEW_ID 2
OLD_CAN_ID 0x601，命令中写作 601
NEW_CAN_ID 0x602，命令中写作 602
NEW_ID_INT32_LE 02000000

# 操作前检查

  • 确认当前使用的 CAN 接口名称和波特率。
  • 记录当前 Motor ID，并计算 OLD_CAN_ID。
  • 确定目标 Motor ID，并计算 NEW_CAN_ID。
  • 将目标 Motor ID 转换为 NEW_ID_INT32_LE。
  • 检查目标 ID 是否会与总线上的其他模组冲突。
  • 修改多个模组时，尽量一次只连接或使能一个目标模组。

# 标准操作流程：ID 1 修改为 ID 2

以下命令以 OLD_ID=1、NEW_ID=2 为例。其他 ID 不可直接照抄，应先重新计算 CAN ID 和小端数据。

# 1. 查询旧 ID

cansend can1 601#6724000000000476

# 2. 修改 Motor ID

cansend can1 601#6724020000001576

其中，02 00 00 00 是新 ID 2 的 32 位小端表示。

# 3. 查询新 ID

cansend can1 602#6724000000000476

# 4. 保存到 Flash

cansend can1 602#6700000000000076
sleep 2

# 5. 再次确认

cansend can1 602#6724000000000476

# 操作后检查

  • 新 CAN ID 能够正常响应查询。
  • 旧 CAN ID 不再作为该模组的有效地址。
  • 保存到 Flash 后等待至少 2 秒，再执行确认查询。
  • 模组重新上电后，ID 仍保持为新值。

# 轮询 Motor ID

下面的脚本依次查询 Motor ID 0 到 20。对应 CAN ID 按 0x600 + Motor ID 计算，并格式化为三位十六进制数。

建议同时在另一个终端运行 candump -e -x can1，观察哪些 CAN ID 返回响应。

for i in $(seq 0 20); do
    canid=$(printf "%03X" $((0x600 + i)))
    echo "Query Motor ID $i -> CAN ID $canid"
    cansend can1 "${canid}#6724000000000476"
    sleep 0.2
done

如需扫描其他 ID 范围，修改 seq 0 20 的起止值即可。轮询只负责发送查询帧，是否存在对应模组仍需根据接收到的响应判断。
